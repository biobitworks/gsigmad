# Skills Layout

The `gsigmad-*` framework skills live at `skills/gsigmad-*/SKILL.md` in this
repo. Every one is the source of truth for its routing surface; runtime
installs (Claude Code's `~/.claude/skills/`, Codex's `~/.codex/skills/`) are
symlinks back to these files.

## Tracked anchors

All `skills/gsigmad-<name>/SKILL.md` files **except one** are tracked in git
and reviewed via PR. New skills are added by writing a `SKILL.md` under a new
sibling directory.

## Untracked anchor: `skills/gsigmad/SKILL.md`

The bare anchor directory `skills/gsigmad/` (no hyphen suffix) is
**intentionally gitignored** at `.gitignore` line 41:

```
skills/gsigmad/
```

with the comment:

> Live symlink to canonical gsigmad source repo (per Watchtower memory:
> "gsigmad runtime install"); do not track

Practically:

- This anchor file exists on disk for runtime skill discovery — Claude Code
  and Codex resolve the `gsigmad` invocation through it.
- Edits to this file are **local-only**. They do not propagate via git.
- The operative routing surface — triggers, routing tables, claim ceilings,
  hard stops — lives in the **tracked** sibling skills, primarily:
  - `skills/gsigmad-quick/SKILL.md` (triage table, three-way distinguisher,
    hard stops)
  - `skills/gsigmad-governance-bridge/SKILL.md` (Antigence routing semantics)
  - the per-lane import / ingest / audit SKILL.md files
  (`gsigmad-import-*`, `gsigmad-ingest-*`, `gsigmad-audit-*`)

## Why the divergence is acceptable

Three reasons:

1. **The tracked files cover the operative behavior.** A reader following any
   triage chain reaches the canonical routing through the tracked skills. The
   anchor file is convenience — it does not encode any contract not also
   encoded in the tracked siblings.
2. **The anchor may be regenerated by runtime install tooling.** Tracking it
   would create merge conflicts every time install tooling regenerates it.
3. **The `.gitignore` line precedes this lane work** and reflects a prior
   operator decision. Reverting it requires its own PROMPT.

## What this means for new routing additions

When adding a routing surface to gsigmad:

- Edit the relevant `skills/gsigmad-<name>/SKILL.md` (tracked). This is the
  source of truth.
- Optionally also update `skills/gsigmad/SKILL.md` (untracked, local) so the
  bare-name invocation surfaces the routing immediately on this machine.
  This step is convenience — the operative routing is already in the tracked
  file.
- Verify with `rg` that the routing surface appears in at least one tracked
  SKILL.md file.

## How to revert this divergence

If a future operator wants the anchor tracked:

```bash
# 1. Remove the line from .gitignore
sed -i '' '/^skills\/gsigmad\/$/d' .gitignore
# 2. Force-add the file
git add -f skills/gsigmad/SKILL.md
# 3. Commit
git commit -m "chore(gsigmad): track anchor SKILL.md as part of routing surface"
# 4. Decide who owns regeneration (runtime install tooling or repo)
```

That choice is deferred until a concrete need surfaces.
