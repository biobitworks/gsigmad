# Runtime Adoption Matrix

Status: public beta adoption proof for `gsigmad 1.2.0b1`.

The authoritative local receipt is generated by:

```bash
uv run python scripts/adoption_matrix_smoke.py --update-corpus
```

That command creates fresh disposable repos, runs the local governance
lifecycle, and writes:

- `examples/projects/adoption_matrix.v1.2.0b1.json`
- `examples/projects/kb_index.v1.2.0b1.json`
- `examples/projects/adoption_matrix_receipt.v1.2.0b1.json`
- `examples/projects/v1.2.0b1/*/README.md`

## Project Coverage

| Project shape | Standalone gsigmad | GSD + gsigmad | Purpose |
| --- | --- | --- | --- |
| Generic Python science | tested | tested | basic local experiment lifecycle |
| Computational biology | tested | tested | biological claim-boundary wording |
| Bioinformatics pipeline | tested | tested | pipeline manifest and reference-data risks |
| Math/modeling notebook | tested | tested | model identifiability and notebook replay risks |
| Data-analysis-only | tested | tested | cleaning/exclusion/environment risks |
| Non-science software repo | tested | tested | engineering evidence vs scientific evidence boundary |

Each case exercises `init`, `status`, `register`, `run --dry-run`, `audit`,
`redteam`, status replay, returned EXP id reuse, prompt/EXP/lab-notebook
artifacts, missing-adapter behavior, and no live writeback.

## Runtime Coverage

| Runtime | Public support | Matrix behavior | Boundary |
| --- | --- | --- | --- |
| ChatGPT Codex / OpenAI Codex | supported | `gsigmad init` installs `.agents/skills/gsigmad/SKILL.md` | edits repo files and follows skills; no truth authority |
| Claude Code | supported | `gsigmad init` installs `.claude/skills/gsigmad/SKILL.md` | edits repo files and follows skills; no truth authority |
| get-shit-done | optional | combined path runs `get-shit-done-cc --codex --claude --local --profile=core` when available | owns project workflow scaffolding, not science claim promotion |
| Ollama | optional | recorded as `configured` when `http://127.0.0.1:11434/api/tags` responds, otherwise `not_configured` | local model backend only; no gate override |
| Ollarma | optional | recorded as `configured` when `http://127.0.0.1:8484/health` responds, otherwise `not_configured` | local bridge receipts only; no claim promotion authority |

To start optional local runtimes:

```bash
ollama serve
ollarma serve
curl -sS http://127.0.0.1:8484/health | jq '.status, .startup_readiness.status'
```

## Knowledge Base

`examples/projects/kb_index.v1.2.0b1.json` is the public local KB seed. It
maps each use case to:

- command sequence
- expected artifacts
- failure modes
- runtime status notes

It is intentionally small and static so downstream users can load it into a
local assistant, docs site, or search index without private adapters or private
experiment data.

## Non-Claims

This matrix is not a ratified scientific benchmark, not a DOI-backed dataset,
not a proof of domain correctness, and not evidence that `gsigmad` validates
truth. It is an out-of-the-box adoption proof for local governance mechanics.
